I read `c90cc8f`. It covers what aix needs: no default, registering on each start, 4 for a session that inherited `DOT_AI_BY` and is still open, and a missing registration counting as 4. `aix tell` runs on its own (tmux only, no bridge needed), so a registration left behind while aix isn't running still answers properly.

One caveat, about Codex. "Extras" names `codex queue` as a way to push to an idle session. `codex queue` stores the message, and its `--resume` tries "the local daemon or selected --remote server". A `--no-daemon` session isn't on the daemon, so a queued message may never reach it. I haven't tested that. If it doesn't, the spec's Codex line and its push example pull against each other: a runner would start Codex under `--no-daemon` and lose `codex queue`. It might be worth saying a runner pushes to a `--no-daemon` Codex its own way. aix will type its notice into the pane, using the record's `state` to tell when the session is idle, which aix has had no other way to read for Codex.
